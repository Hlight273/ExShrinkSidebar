# 缺陷修复交付

迁移自源项目同名技能，适配当前 WPF 工程。使用前说明名称与用途。

## 输入与边界

确认实际表现、期望表现、触发条件及已有日志/堆栈；按需定位相关模块和最近变更。信息不齐时先做可独立推进的只读排查，影响根因判断的关键缺口再澄清。不把新需求当成修复，也不声称未经复现的推断已被证实。

## 上下文与排查

- 遵循根目录 [AGENTS.md](../../../AGENTS.md)，通过 [business-context-router](../business-context-router/SKILL.md) 选择主规格、架构章节、目标代码及直接依赖，不重复加载已读内容。
- 区分 WPF 视图、核心状态、配置模型、Windows/COM 适配和构建环境问题；入口为 App.xaml.cs，不使用其他项目的端侧划分。
- 配置问题检查 ConfigManager、ButtonConfig、ResHelper 与编辑器工作副本；定位实际用户配置路径，不直接覆盖真实配置复现损坏文件问题。
- 停靠问题检查 DockState、DockManager、MainWindow、ScreenHelper 和 Hook 的坐标、DPI、状态与释放链。
- UI 更新检查 Dispatcher、事件触发线程和订阅生命周期；动作问题追踪 BtnCfgLogicRunner 与 ExplorerWindowHelper。
- 构建中的 MSB4803 先核对完整 MSBuild 工具链，不删 COM 引用绕过环境限制。

## 执行流程

1. 描述现象和影响面，从日志、调用链、数据来源及相关差异建立证据。
2. 给出根因或待验证假设，区分代码缺陷、数据问题和环境限制。
3. 给出文件级修复方案、为何能消除根因、副作用与验证场景。编码遵循 AGENTS.md 的方案流程和当前有效授权；只要求分析时不修改代码。
4. 实施最小必要修复，不夹带无关重构。不能只吞异常或加判空而掩盖未处理的数据契约错误。
5. 按 AGENTS.md 验证矩阵检查复现路径、相关边界和回归路径。新增测试产物遵循授权规则；无法运行 UI 时明确未验证项。
6. 恢复既定行为无需创建空 OpenSpec 提案；若改变行为或兼容约定，先记录变更，完成后同步主规格及文档。

## 交付

说明根因及证据、修改范围、实际验证结果和剩余风险。区分源码推断、构建结果与运行验证，不能把猜测写成已复现结论。
