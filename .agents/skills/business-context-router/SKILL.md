# 业务上下文路由

只负责选择上下文，不替代实现、验证和 OpenSpec 交付流程。使用前说明名称与用途；已读且未变化的 AGENTS.md 不重复加载。

## 选择流程

1. 识别业务能力、任务性质、涉及层级（WPF 视图、核心状态、配置模型、Windows 适配、资源/发布）。
2. 先列路径与标题再读内容：rg --files openspec/specs、搜索 docs/FrameworkArchitecture.md 的标题，以及需求对应符号。
3. 从 [主规格索引](../../../openspec/README.md) 选择相关能力，通常从一至三项开始；这不是硬上限，有跨能力依赖则扩展。
4. 有活动 change 时检查其目标和状态，完整读取 OpenSpec apply 指令返回的 contextFiles；不为节省上下文跳过必需文件。使用本机可用 CLI，不假设 /opsx 快捷命令已安装。
5. 阅读 [架构文档](../../../docs/FrameworkArchitecture.md) 相关章节及目标代码，再沿调用方、直接依赖、事件订阅/释放、数据所有权和线程边界扩展。涉及 Win32/COM 时查现有声明和平台接口契约，不猜签名。
6. 信息足以解释目标行为、依赖边界和验证方式后停止扩展，简述路由结果并继续当前任务。

## 发现入口

| 任务线索 | 主规格候选 | 架构章节 |
| --- | --- | --- |
| 显隐、边缘、DPI、展示序号 | dock-sidebar | 停靠与显示器 |
| JSON、旧字段、配置 ID | config-storage | 配置所有权与保存 |
| Execute、目录、动作顺序 | action-execution | 动作执行与平台适配 |
| 树节点、详情、保存、拖拽 | config-editor，按需补 config-storage/dock-sidebar | 编辑器与配置链路 |
| 托盘、语言、退出 | tray-localization | 启动与退出；本地化与资源 |

此表是发现入口，实际依赖以代码为证据。发布工具等未规格化内容从工程文件和 AGENTS.md 建立上下文，不创建空业务规格。

## 来源与冲突

- 主规格表示当前约定行为；活动 change 表示本次目标；代码表示实际实现；架构表示职责边界；归档是历史证据。
- 不因代码存在就把缺陷写成规范；不把尚未实施的 change 当成当前行为。
- 无对应主规格时说明“该能力尚未规格化”，使用代码和架构继续分析；新功能在 change 中定义，实施后同步。
- 记录冲突位置及影响。当前请求或已确认目标能解决的差异直接处理；影响业务语义、兼容性且证据不足的关键分歧再澄清。
- 默认不读 archive。仅在用户追溯历史、排查回归/旧数据、当前证据无法解释冲突或 change 引用历史时，筛选最相关归档，再按需扩展。

## 路由摘要

简述能力、主规格、活动 change（或无）、架构章节、代码范围、验证层级和是否读取历史及原因。不复述文件全文，也不使用固定全量阅读清单。
