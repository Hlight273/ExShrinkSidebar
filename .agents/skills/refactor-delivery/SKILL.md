# 重构交付

迁移自源项目同名技能，适配当前 WPF 工程。使用前说明名称与用途。

## 范围与基线

明确结构问题、涉及模块及验收方式，默认保持业务行为不变。允许变化的行为单独列出并按 OpenSpec 管理；不以重构掩盖缺陷或扩大为框架重写。

## 流程

1. 阅读 [AGENTS.md](../../../AGENTS.md)，通过 [business-context-router](../business-context-router/SKILL.md) 选择相关规格、架构和调用链；已读未变化的内容不重复加载。
2. 说明当前结构问题和依赖关系；核对 [FrameworkArchitecture.md](../../../docs/FrameworkArchitecture.md) 中的状态所有权、线程和生命周期。
3. 给出文件级方案、收益、保留的行为及验证方法。遵循 AGENTS.md 的方案流程和当前有效授权；用户只要求方案时不改代码。
4. 实施聚焦修改，同步调用方、命名空间、XAML x:Class、事件绑定、资源路径和项目项中实际受影响的引用。
5. 按 AGENTS.md 执行适用构建与关键路径验证，记录未覆盖项；不为纯结构调整改写业务主规格的含义。
6. 更新发生变化的架构边界；确有行为变化时同步对应 change 与主规格。

## 自检重点

- 不将当前 code-behind 项目未经授权改造成全量 MVVM，不凭未来复用需求引入新框架。
- 保持 ConfigManager 正式配置与编辑器工作副本隔离，维持旧字段兼容及全树 ID 预留。
- 不改变动作展开顺序、失败处理、Dock 展示筛选或配置枚举持久化数值。
- 保持 WPF Dispatcher 边界、物理像素/DIP 换算、窗口重建后的订阅与释放。
- 检查 EVENT 监听者、Hook、计时器、托盘和 COM 相关资源生命周期。
- 资源和 Designer 文件从源文件或生成流程维护；不要直接编辑生成产物。

## 交付

说明结构改善、修改范围、行为基线如何核对、实际验证结果和未覆盖风险。“行为不变”是需要证据支持的目标，不能因构建通过就宣称完整回归通过。
