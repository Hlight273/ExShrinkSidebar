# Git 差异审查

迁移自源项目同名技能，适配当前 WPF 工程。使用前说明名称与用途。只审查；用户已明确要求修复时，再结合缺陷修复或重构流程处理。

## 范围与证据

- 用户指定文件、补丁、提交区间或基准时按其范围审查。
- 默认通过 git status --short、git diff --cached 和 git diff 检查暂存与未暂存差异，并读取明显相关的未跟踪文件。新文件不在普通 diff 中，不得遗漏或仅按文件名判断。
- 对同一文件同时有暂存和未暂存修改的情况，区分两个状态与最终工作区内容；发现必须对应实际审查版本。
- 先读差异，再补读受影响函数、调用方及直接依赖。截断时按文件继续，不以统计量替代审查。
- 业务改动使用 [business-context-router](../business-context-router/SKILL.md)，并遵循根目录 [AGENTS.md](../../../AGENTS.md)。纯文档审查不强制读取全部业务规格。
- 无法读取仓库或补丁时说明限制；可以继续评审已提供的内容，不编造未看到的差异。

## 项目重点

1. App 启动、窗口重建、重复初始化、遗漏清理或托盘退出行为。
2. UI 线程访问、EVENT 调用线程、订阅重复或释放不完整，特别是捕获闭包的 Target。
3. Dock 边缘与显示器选择、DPI/物理像素混用、拖动暂停恢复、容量和重复展示序号。
4. 配置深拷贝、正式对象误修改、旧 script 字段兼容、父引用、ID、序列化枚举及保存失败影响。
5. 动作展开顺序、失败是否继续、后台任务与外部进程生命周期、Explorer 重排契约。
6. XAML x:Class、绑定和事件处理器、资源 URI、Build Action、CopyToOutputDirectory 与发布目录。
7. SHDocVw COM 构建约束；不得为绕过构建错误删平台功能。
8. 本地化源资源与生成文件一致性。生成产物的变化应追溯源数据/生成流程，不能仅凭文件变化断言手工修改违规。
9. 未实现的半截功能、死代码、无关改动和主规格漂移。规范问题与实际功能缺陷分开说明，不把个人风格偏好升级为阻塞项。

## 输出

问题优先，按 P0（紧急）、P1（高）、P2（中）、P3（低）排序。每项给出当前版本的准确路径及紧凑行号、触发条件、实际影响、代码证据和最小修复方向。

仅报告差异引入或加剧的可操作问题；既有问题如与任务有关，应明确标为背景。推测性风险说明缺失证据，不当作已确认缺陷。不为凑数输出问题，不将同一根因重复拆项。

未发现明确问题时直说，并列出验证盲区。区分实际执行的检查与建议补充的检查；没有现成测试不等于每次必须新建测试文件。不得把静态审查写为已完成运行验收。
